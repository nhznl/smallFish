📗 Wheel Explainer

Reference for the Wheel Scan tab. It explains what every historical-scan column means, the terminal-vs-touch distinction, why these numbers are descriptive, not predictive, and how to read the sample counts. It also distinguishes the scan from the separate Option Quotes archive. Source of truth: models/wheel.py (WHEEL_COLUMNS), utilities/options/config/wheel.yaml, and Requirements.md.

⚠ Read this first — analytics tooling, not trade selection

Every frequency on this tab is computed over historical overlapping windows spanning mixed market regimes. Overlapping windows are autocorrelated, so these are not confidence-interval-grade probabilities — they describe what the stock did, not what it will do. The Wheel Scan makes no claim about actual option premiums, fills, or assignment odds: realized-vol percentile is only underlying-volatility context. The separate Collect Option Quotes action discovers exact contracts and archives Tastytrade quotes under its own quality contract. There are no trade recommendations here.

1. What "good for wheeling" decomposes into

  • Am I OK owning this at the strike? — the trend/structure classification. Wheel does not treat a momentum score as an ownership-quality score.
  • Is underlying realized volatility elevated relative to itself? — RV and its 252-day percentile. A high percentile is only context; the separate quote collection records actual contract quotes.
  • How often did price historically finish beyond a comparable hypothetical strike? — the 1σ terminal move and historical expiry-ITM frequency. This is not an assignment probability.
  • Is a known earnings event inside the window? — shown with explicit freshness (the tri-state Earnings column).

2. Terminal (expiry-ITM) vs Touch — the key distinction

For each historical window the hypothetical strike is set from that window's own entry close, and only the future-only interval after entry counts (the entry day's own high/low never counts).

MetricDefinitionReads as
Expiry-ITM (terminal) The terminal close at expiry breaches the strike (put: final close ≤ put strike; call: final close ≥ call strike). Historical terminal-close breach frequency
Touch Price breaches the strike any time in the window — put side uses the minimum future daily low; call side uses the maximum future daily high (never closes). Historical intrawindow breach frequency

Both are reported. Touch is always ≥ terminal, but no fixed "touch ≈ 2× terminal" ratio is claimed — the relationship varies by name and horizon. American options can also be assigned early, which is why the honest label is "expiry-ITM frequency", not "assignment odds".

3. Sample-count guidance

Every frequency ships with two sample counts: all overlapping windows and a disjoint subset selected at one-horizon strides. Hover the table frequency to compare both estimates. The disjoint diagnostic removes direct window overlap but does not eliminate market-regime or repeated-symbol dependence, so neither figure is a forecast or confidence guarantee. Treat small counts as noisy. In the table, overlapping counts below 60 are highlighted.

The Wheel table's Samples > filter applies only to the primary overlapping count; it does not replace or filter on the disjoint diagnostic.

4. Volatility & expected-move conventions

  • RV (realized volatility) is stored as daily σ. Two estimators are computed: close-to-close (sample std of log returns) and Parkinson (a high/low range estimator that misses overnight gaps). The scan uses rv_used = max(σ_cc, σ_park) — the conservative convention.
  • RV Rank is (current RV − trailing low RV) ÷ (trailing high RV − trailing low RV) over the same trailing 252-session 21-day-RV series. It is unavailable when the high and low are equal.
  • RV %ile is today's 21-day RV as a percentile of its own trailing 252 sessions — a percentile, not a "vol rank".
  • 1σ move = spot × rv_daily × √N (N = exchange sessions in the horizon, N = round(DTE × 252/365)). Labelled a historical-vol, normal-model approximation — not a 68% guarantee.
  • ATR14% is the latest 14-session Average True Range expressed as a percentage of the latest close: ATR14 ÷ spot. For each day, True Range is the greatest of high − low, |high − previous close|, and |low − previous close|. The app applies Wilder smoothing to those daily ranges, seeded with the first 14-session average. This makes ATR14% a recent daily range-and-gap heuristic, not a standard deviation or an expected move.

Example — $90 stock: a selected-horizon 1σ move of 12% is about $10.80, giving a rough terminal range of $79.20 to $100.80 under the historical-volatility normal-model approximation. An ATR14% of 4% is about $3.60: the recent typical one-session true-range scale, including gaps. It does not mean the stock is expected to move exactly $3.60 tomorrow, and it should not be multiplied into a horizon forecast. The 1σ figure is horizon-scaled from realized-volatility estimates; ATR14% is a backward-looking daily range heuristic.

5. Earnings freshness — the tri-state

A blank "no earnings" is dangerous when the events file is stale, so the Earnings column is a tri-state, evaluated per horizon (a horizon counts as covered only when the events coverage reaches price_as_of + horizon calendar days):

StateMeaning
⚠ Known eventAn earnings date falls inside this horizon's window.
None in rangeNo earnings in the window and the events data freshly covers it.
Unknown (stale)The events file does not cover this horizon — treat as unknown, never as "no earnings".

6. Null rendering

Several fields are legitimately absent and render as "—", never 0 or "failed":

  • Trend — symbols with insufficient history have no trend result; the field is "—", which is expected, not an error.
  • Days to Event / RV %ile — may be blank when the underlying data isn't available.

Hide-bearish toggle: default-on, it hides a row only when the trend direction is BEARISH. A null/absent trend ("not evaluated") is never hidden.

8. What the Wheel Scan does NOT do

  • No actual option premiums, bids, asks, or IV in this report — the separate quote collection archives exact-contract Tastytrade observations.
  • No option-liquidity gate in this report — only the underlying's dollar volume is visible here.
  • No trade recommendations, no auto-trading — this is analytics and journaling only.

9. Wheel Scan vs Option Quotes

ViewWhat it containsWhat it does not mean
Wheel Scan Local OHLCV-derived history across the displayed 7, 14, 30, 37, and 45 DTE horizons. A selected contract, live premium, fill, assignment probability, or recommendation.
Option Quotes The latest immutable archive of exact contracts and Tastytrade bid/ask observations, including timestamps, quality, OI/spread checks, and entry gates. A live refresh when opened: opening, filtering, and refreshing this tab only reads the archive.

Collect Option Quotes is the only UI action here that contacts Tastytrade. It uses the current Wheel view's Horizon, OTM cushion, and filtered symbols. Filter to Holdings limits that view to the union of current Trading and Retirement equity holdings; if either holdings source is unavailable, it leaves the table unchanged. The configured quality/liquidity gates still apply, then at most 60 eligible symbols are retained by RV percentile. In the quote archive, ENTRY is a strike-selection view; it is not the same as entry_eligible.
